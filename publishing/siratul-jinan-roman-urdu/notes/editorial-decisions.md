# Sirat-ul-Jinan Editorial Decisions

## Source of Truth

The focused SQLite database at `source/siratul-jinan.db` is authoritative for source text, identifiers, ordering, and Quranic mapping. Generated batches and manuscript files are derived working and publishing outputs.

## Transliteration, Not Translation

The output converts the Urdu script into Roman script. The Urdu vocabulary, grammar, sentence order, and meaning are preserved exactly; only the script changes. Do NOT paraphrase, reword into English, or "translate" the meaning. Quranic Arabic, Arabic duas, hadith quotations, Islamic phrases, and Arabic honorifics remain in Arabic script and are never romanized. Approved spellings are recorded in `notes/glossary.md`.

## Pilot-First Workflow

Transliteration begins with Surah Al-Fatihah. Full-volume transliteration must not begin until the pilot's style, romanization, formatting, terminology, and review conventions are approved.

## Arabic Preservation

Arabic phrases inside `{...}` blocks remain in Arabic script. Their Urdu meanings are converted to Roman script. Quranic Arabic and Arabic quotations are never replaced with transliteration.

## Source Identifiers

Each working transliteration entry remains traceable to `tafseerId`, `ayatId`, surah, ayat number, para, and volume. Reader-facing exports may hide implementation identifiers only after validation is complete.

## File Size Limit

New or substantially changed files must contain at most 2,000 lines. If a file would exceed
that limit, split it at a logical entry or section boundary without splitting sentences,
quotations, citations, or traceable transliteration entries. Existing files that already
exceed 2,000 lines are grandfathered and may remain unchanged unless they are otherwise
being edited.

## Open Decisions

- Final reader-facing heading format for ayat entries.
- Final treatment of source citations and footnotes in the exported editions.
- Final details of the Urdu → Roman romanization scheme for remaining edge letters.

## Transliteration Validation (`--mode transliteration`)

The validator (`scripts/validate_siratul_jinan_translation.py`) enforces, in transliteration mode:

- **NFC normalization both sides.** The source DB stores combining marks in a non-canonical order (shadda before fatha), while the roman manuscript uses canonical order (fatha before shadda). Both sides are NFC-normalized before any comparison so visually identical text compares equal.
- **Quranic ayat runs present.** Every Arabic run of `aayaat.arabicText` (normalized) must appear in the batch.
- **`{...}` block headings present.** Every Arabic heading extracted from DB `tafseerTextPlain` `{...}` blocks (text before the first `:`) must appear verbatim in the batch.
- **No introduced Arabic.** Every Arabic run in the batch must be a verbatim substring of the DB source (tafseer text + aayaat text, normalized). This caught the `اَ لْاَمْنُ` spacing issue below.
- **No leftover Urdu punctuation.** Urdu quote characters (`’`, `‘`, `«`, `»`) must not remain in a roman batch — all quotes must be converted to doubled ASCII apostrophes (`''`).
- **Structural parity.** `{`/`[` counts and numbered-item counts (matching `\([0-9۰-۹]+\)`) must equal the DB source.
- **No artifacts.** No `($1)` replacement artifacts, no HTML tags, and enough Latin prose to confirm transliteration happened.

## Verbatim Arabic, Including Source Quirks

Arabic must be preserved exactly as it appears in the source, even where the source is inconsistent. Example: the A'la Hazrat risala title appears in the DB as `اَ لْاَمْنُ وَالْعُلٰی لِنَاعِتِی الْمُصْطَفٰی بِدَافِعِ البلاء` (with a space inside the first word); the roman batch initially dropped that space to `اَلْاَمْنُ`, which the validator flagged and the manuscript was corrected to match the source.

## Quote Marks

The DB's quote encoding is internally unbalanced (82 doubled `’‘` open marks vs 70 doubled `‘«` close marks across the pilot rows — several hadith quotes lack a close mark). The roman manuscript therefore normalizes every quote to balanced doubled apostrophes (`''...''`), and the validator checks only that no Urdu quote characters remain rather than requiring count parity.

## Numbered Single-Surah Manuscript Convention (2026-08-22)

Per-batch roman files are superseded by numbered append-only manuscript parts per surah
(e.g., `02-surah-al-baqarah/02-surah-al-baqarah-roman-01.md`).
`scripts/consolidate_siratul_jinan_batches.py` rebuilds the parts from archived batches
plus `_inserts/insert-ayat-*.md` files,
splits multi-entry batch blocks into per-entry blocks, sorts by ayat number, and verifies
every `(ayat number, tafseerId)` pair against the DB via the `aayaat` join (`surahId=2`)
before writing. Each part is at most 2,000 lines and entries are never split between
parts. The legacy `surah-al-baqarah-roman.md` file was grandfathered, then replaced by
numbered parts when the file-size rule was applied.

## Non-Monotonic tafseerIds

`tafseerId` values are NOT globally ordered by ayat: rows 54501–54522 are genuine
Al-Baqarah entries appended late at the end of the ID space (e.g., ayat 2:12 →
tafseerId 54504). Ordering must be verified by **ayat number** (via `ayatId` →
`aayaat`), never by tafseerId. The batch-register's "Source batch (tafseerIds …)"
notes reflect this interleaving; the extractor emits them in DB order within each
batch, and the consolidator restores Quranic order.

## Cross-Reference Entries (2:36, 2:39, 2:46)

Ayats 2:36 (tafseerId 54507), 2:39 (54508), and 2:46 (54509) have real DB rows that
were skipped during batch extraction because they fall between approved ranges. All
three are one-line cross-references stating the tafseer was covered under the previous
ayat. They are transliterated with the exact Batch 24 (2:52) precedent wording —
"Is aayat ki tafseer guzishtah aayat ki tafseer ke zimn mein bayaan ho chuki hai." —
and staged as `_inserts/insert-ayat-{36,39,46}.md` for the consolidator to splice.
Their Arabic is byte-exact from the DB, including the standalone U+065B combining
mark surrounded by spaces before `(46)` in 2:46 and four trailing spaces before `(39)`
in 2:39. Ayat 2:2 has no tafseer row in the DB at all and is legitimately absent
(the only gap in 1–113).
